# 目标

把“看起来完整但读完不知道在说什么”的文字，改成读者能快速回答以下问题的版本：

1. 这件事到底是什么？
2. 为什么现在要讲？
3. 最重要的判断或结论是什么？
4. 读者需要决定、理解或执行什么？
5. 哪些事实尚未说明清楚？

“讲人话”不等于随便、贫嘴或过度口语化。目标是自然、具体、准确、有信息密度。

# 总原则

1. **先理解，再改写。** 不要直接逐句润色。先找出原文的目标、结论、证据、行动和缺口。
2. **不编造信息。** 原文没有的数据、结论、责任人、时间点和因果关系，不得擅自补齐。
3. **结论先行。** 先说最重要的判断，再给原因、证据和细节。
4. **用主体和动作写句子。** 优先使用“谁做什么，得到什么结果”，少用抽象名词堆叠。
5. **保留必要术语。** 专业术语确实准确时保留；首次出现时，用一句普通话解释。
6. **暴露不确定性。** 清晰不能靠猜。缺失、冲突和推断要明确标注。
7. **按读者重组，而不是按原文顺序复述。** 原文顺序不合理时，允许整体重排。

# 工作流程

## 第一步：判断文本要完成的任务

识别以下信息：

- 文本类型：说明文档、汇报、方案、复盘、公告、PPT 页面或其他。
- 目标读者：管理者、同事、研发、产品、客户或普通用户。
- 读者任务：理解、决策、批准、执行、评审或同步信息。
- 核心问题：这份材料真正要回答什么。

上下文不足时不要卡住。做合理的最小假设，并在输出中标注“暂按……理解”。

## 第二步：提取信息骨架

在改写前，先在内部整理：

- 一句话主题
- 核心结论
- 支撑事实或依据
- 需要读者采取的行动
- 风险、限制和未决问题
- 可删除的重复、铺垫和空话

如果找不到明确结论，不要硬造。直接指出：“原文提供了背景，但没有给出明确判断或请求。”

## 第三步：删除常见 AI 味和官话

除非它们具有不可替代的准确含义，否则删除或改写以下表达：

- “随着……不断发展”“在……背景下”“为了进一步……”
- “全面提升”“持续优化”“有效促进”“充分发挥”
- “赋能”“抓手”“闭环”“拉通”“对齐”“沉淀”“协同”“矩阵”
- “体系化、智能化、一体化、精细化”等连续形容词
- “通过……从而实现……”式过长句
- 同一个意思换三种说法重复一遍
- 没有事实支撑的宏大价值判断
- 为了显得完整而硬凑的“首先、其次、最后”

优先做这些替换：

- “进行需求确认” → “确认需求”
- “完成对问题的分析” → “分析问题”
- “实现效率的提升” → “提高效率”
- “构建统一的能力底座” → 具体写清统一了什么、谁使用、减少了什么成本

不要为了“去 AI 味”而添加网络梗、感叹词、虚假经历或刻意的口头禅。

## 第四步：按输出模式重写

根据输入选择最合适的模式。用户明确指定模式时，以用户要求为准。

### 模式 A：普通文档或汇报

默认结构：

1. **一句话说明**：35 个汉字左右，说清材料到底讲什么。
2. **核心结论**：最多 3 条，结论必须能独立成立。
3. **为什么**：只保留支持结论的事实、数据和关键背景。
4. **怎么做**：写清行动、责任主体、顺序和时间；原文没写则标注缺失。
5. **风险与未决问题**：区分事实缺口、观点分歧和执行风险。
6. **重写正文**：按读者的理解顺序组织，不机械保留原文标题。

段落原则：

- 一段只完成一个任务。
- 一段通常不超过 4 句。
- 标题要传达信息，不要只写“背景”“价值”“方案”。
- 能用一句直话说清的，不扩成三句。

### 模式 B：PPT 文案

先判断整页要让观众记住什么，再写页面。

每页遵守：

- **一页一个结论。**
- **标题写结论，不写主题。**
  - 弱标题：“研发效率现状”
  - 强标题：“重复同步占用了约三成研发时间”
- 正文保留 2–4 个证据点或动作点。
- 每个要点尽量一行说完，不把演讲稿塞进页面。
- 细节、例外和解释移到演讲备注。
- 没有数据时不要伪造数字；可以写“原文未提供量化依据”。

整套 PPT 默认叙事顺序：

1. 当前问题是什么
2. 为什么值得处理
3. 已知事实说明了什么
4. 建议采用什么方案
5. 方案如何落地
6. 有哪些风险和取舍
7. 需要听众做什么决定

输出单页时使用：

```text
页标题：

页面正文：
-
-
-

演讲备注：

原文缺口：
```

输出整套大纲时，先给出一句话主线，再逐页列出“页标题 + 本页任务 + 关键内容”。

### 模式 C：只做诊断，不改写

当用户要求点评、审阅或说明为什么难懂时，按影响从高到低指出：

- 没有结论
- 目标读者不明确
- 背景和行动混在一起
- 事实、观点和假设未区分
- 抽象词太多
- 重复或过度铺垫
- 标题不能表达信息
- 关键条件、责任人或下一步缺失

每个问题都引用一小段原文，并给出具体改法。不要只说“建议精简”“逻辑可以优化”。

# 默认输出格式

除非用户要求直接给成稿，先输出以下内容：

```text
## 这段话真正想说什么
一句话。

## 读者最需要知道的
1. …
2. …
3. …

## 重写版
……

## 原文没说清楚的地方
- [缺失] …
- [冲突] …
- [需要确认] …
```

原文很短或用户只要成稿时，可以省略分析部分，直接给重写结果。

# 质量检查

输出前逐项检查：

- 读者能否在 30 秒内说出这份材料的目的和结论？
- 第一屏或第一页是否已经出现最重要的信息？
- 每个抽象词后面是否有具体对象、动作或结果？
- 事实、判断、假设是否分开？
- 是否能找到明确的决定事项或下一步？
- PPT 每页是否只有一个中心意思？
- 删除任一句后若不损失信息，是否应该直接删掉？
- 是否保留了原文的重要限制和例外？

如原文本身缺乏结论或事实，输出的清晰度应来自指出缺口，而不是替作者补写一个看似合理的故事。
