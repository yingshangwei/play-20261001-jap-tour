## 绑定当前手账

`getJournalDay` 以不可变方式附加 `DayJournalWeather`。日期取手账，时区取当前攻略，点位与坐标取该日期的 `GuideDay` 和 `Place`；通过 `pointsForDay` 保留路线中的中途返店和最终返店。请求按地点 ID 去重，分时展示保留每次停靠。

交通时间取权威 `TransitLeg`：起点取出发说明中的首个时刻，之后取到达说明中的末个时刻（避免把中转站当作最终目的地）。这是交通文字中可识别的代表时刻；未解析出时刻则显示“时间待定”，不猜测。当前分时卡展示该时刻所在整点的预报，原始交通时间说明同时保留。下一阶段若覆盖整段停留，应扩展结构化时间模型，不能另造一套天气时间线。

共享组件不导入攻略包。两套关西配置及 `sample-weekend` 的 `hand-journal` / `compact-journal` 模板均使用同一模块，卡片放在路线摘要之后、时间线之前。客户端组件键包含 `guideId` 与日期，切换后重置选点、展开与请求状态。

## 数据源与日期语义

使用 [Open-Meteo Forecast API](https://open-meteo.com/en/docs)，浏览器直接请求公开接口，无密钥或服务器依赖。参数传入所有当天地点的经纬度、攻略时区、相同的 `start_date` / `end_date`；单位为 °C、km/h、mm。多地点响应按请求顺序映射，数量不符即拒绝，部分地点缺失不借用其他地点数据。

按 2026-09-05 用户补充要求，卡片底部不再展示来源链接和整段预警／停运说明；保留数据时刻旁的简短“模型估算”标注。

| 手账日期相对于目的地今天 | 展示 |
| --- | --- |
| 今天 | 请求 `current`、`daily`、`hourly`；展示当前温度、体感、天气、风速、阵风和日温度范围 |
| 明天至第 15 天 | 请求手账日期的逐日与逐小时预报，不请求当前天气 |
| 第 16 天及以后 | 暂不可用，给出手账日前 15 天的预计查询日期 |
| 过去日期 | 说明历史天气尚不支持，不拿今天的天气代替 |

供应商的 `current` 基于 15 分钟天气模型，界面标注“模型估算”；当前降水是 `interval` 指定的此前时段累计，不能标作 mm/h。全天最高降水概率与当前降水分开标注。显示的“获取于”是客户端取数时刻，当前天气另显示数据有效时刻，不能将 `generationtime_ms` 当模型更新时间。

日期判断使用攻略时区，与访问者电脑时区无关。当前数据时间通过响应 `utc_offset_seconds` 转换成时间戳；不同日期或明显位于未来的当前数据不展示。未知天气编码、空值、缺失值显示“暂无数据”，零温度或零降水仍保留零。

## 请求生命周期与异常

- 静态页面构建不请求天气；水合后更新，正文可立即阅读，JavaScript 不可用时提示启用。
- 首次打开、主动刷新、可见页面每 15 分钟取数；恢复可见或焦点时，仅上次请求已满 15 分钟才更新。
- 每分钟只更新日期和数据年龄，跨当地午夜重新判断查询范围；后台不可见时不定期请求。
- 请求 12 秒超时；切页、刷新或组件卸载会取消旧请求，并忽略迟到结果。
- 在当前页面内保留上次成功快照，刷新失败仍可查看并明确标注失败；不写持久缓存。获取时间或选中地点当前天气有效时间超过 1 小时显示过期。
- 部分地点失败时其他地点仍可用；空坐标、无有效响应、HTTP 错误或网络异常不阻断手账。
- 展开、地点选择不因刷新重置。展开按钮提供 `aria-expanded` / `aria-controls`，刷新不抢焦点，状态以文字和 `aria-live` 提示。

## 出行提示边界

以下是产品提示阈值，不是气象部门警报等级：降水概率 ≥ 50% 或降水 ≥ 0.1 mm 提醒带雨具；风速 ≥ 30 km/h 或阵风 ≥ 40 km/h 提醒查看运营公告；体感 ≥ 30°C / ≤ 10°C 提醒饮水休息 / 带外套；雷暴编码提醒核对公告与交通备选。提示旁显示相应天气数值。

分时提醒引用当前交通卡原有 `fallback` 文本及点位 `official` 链接；固定项目仍按手账安排。首版不自动读取预警或停运状态，不能显示“无预警”、声称活动停运或自行变更行程。

## 静态部署兼容

天气端点是绝对 HTTPS 地址，不拼接站点前缀。模块通过现有页面客户端资源加载，兼容 Worker 与 GitHub Pages 静态导出。沿途官网沿用配置中的外部地址；本轮不新增页面路由或修改发布流程。
