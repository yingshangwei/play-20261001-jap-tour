# 旅程播放器设计

视觉方向：浅纸色背景、深绿控制、橘色当前行程。把目的地照片、时间和动作作为主信息；路线带像连续的交通示意图，让读者一直看得见正在去哪，详细换乘信息按需展开。不是地图截图拼接，也不是地理准确的路网。

## 数据和边界

`getJourneyModel` 仍从日期、路线段和交通表派生。播放器不导入具体攻略包。新增通用 `TransportMode`，交通表可显式给出 `transportModes`；无显式值时按已有交通类别保守推断。普通 JR 不等于新干线，备用打车不能成为主交通图标，混合段并列图标而不伪造换乘发生时刻。

`JourneyPlayer` 管理播放；`journeyPlayback.ts` 负责可测试的状态推进和示意曲线；`RouteRibbon` 展示当天顺序；`JourneyLocator` 仅定位起終点。照片仍来自配置并保留署名、区域占位说明和静态部署前缀。未新增或删改任何行程点。

## 静态路线阅读

- 每条连接线上显示主交通图标和名称，未播放也完整可读；行进时本段标签暂由移动的交通图标替代，抵达后恢复，避免图标压住半截文字。
- 节点左侧是本次到达，右侧是本次离开。`routeNodes` 分别保留 `incomingStepIndex` 与 `outgoingStepIndex`，不能按地点 ID 全局合并。起点写“当日起点”，终点写“当日结束”；断段单独标明起止，跨日不借用时间。
- 通常从已有计划提取首个出发和最后到达，并保留估算范围。复杂原文通过攻略的 `displayTimes` 显式提供短标签：贵船巴士站与神社本宫不同、午餐不等于返程出发、返程两个酒店区域时间并列。短标签只是已有计划的显示口径，不代表重新核实班次。
- 每个节点下面是 16:9 实景缩略图，桌面 160×90、窄屏 144×81；图片标签、作者、许可和来源链接保留。首节点从本配置派生的 `fromMedia` 取图，其余使用进入段的 `media`，缺图不跨地点或跨配置补图。
- 图片来源与选点按钮是兄弟元素；点击节点、照片或交通标签可查看对应阶段，手动操作会暂停动画。未开始时不在起点覆盖一个静止交通图标。

## 播放规则

- 单一时钟：每段先行进 6 秒，再按说明长度留 4.5–8 秒阅读。倍速 0.75 / 1 / 1.5 / 2，明确只是预览速度。
- 暂停保留位置，继续与调速不重建路线；最后一段停在到达态，仅点击重播才重置。
- 切日期或手选阶段暂停并归零；无移动安排日禁用。切地图视图保留播放进度。
- 手动拖动路线或地图、展开详情、切入后台、播放器完全离屏均暂停；恢复播放时找回当前路线。
- 地图只在换段时重新取景。路线带仅在切段、恢复或尺寸改变时检查取景，不每帧滚动。
- 系统减弱动态时不做位置平移或渐进描线，保留阶段和到达状态。读屏仅播报当前目的地与到达摘要。
- 一天的路线按访问次数排列，重复回酒店仍保留；断开的原始段不虚构一条连接边。

## 验证

`pnpm run check` 包含纯状态机、运输类型、曲线端点、配置隔离、路线回访、资源前缀和服务器渲染回归。浏览器验收另测桌面、手机、暂停继续、调速、切日、手动滚动后继续、真实地图与缺图示例。详见 [执行记录](../exec_plan/journey-player.md)。
