# 多攻略配置平台需求

## 文档入口

- [仓库文档地图](../../../MAP.md)
- [需求索引](../index.md)
- [配置化架构设计](../../development/guide-platform-architecture.md)
- [重构执行计划](../../exec_plan/guide-config-refactor.md)

## 目标

将旅行攻略框架与具体攻略内容分离，使同一套页面、地图和播放器可以注册并按需加载多套攻略。每日详细手账使用统一抽象模型，同时允许不同攻略或不同日期选择不同视觉模板。

## 范围

- 攻略元数据、日期、点位、路线段和交通信息。
- 首页每日摘要、预订、行李、餐厅、专题和外部链接。
- 地图筛选、点位标记和局部路线箭头。
- 从每日路线派生的旅程动画。
- 每日详细手账的通用章节模型、模板选择和主题资源。
- 攻略注册、动态加载、路由选择与配置校验。

## 功能要求

1. 新攻略通过独立目录提供配置，不在通用组件内增加攻略判断分支。
2. 攻略必须有稳定的 `guideId`，日期、点位和交通段必须有稳定标识。
3. 点位和每日路线只定义一次，地图、交通卡和动画从相同数据源派生。
4. 每日手账内容必须可序列化，不包含 React 节点、组件函数或 CSS 类名。
5. 手账通过模板标识选择渲染器；模板可不同，但共享日期、路线、推荐、备注、链接和来源等领域模型。
6. 每套攻略可以独立声明图片、下载文件及其他静态资源，并正确处理部署路径前缀。
7. 未知攻略、重复 ID、未知点位、缺失交通段、日期冲突和缺失资源应在开发或构建阶段失败。

## 约束

- 关西攻略的固定事实和不可移动锚点以 [AGENTS.md](../../../AGENTS.md) 为准。
- 迁移期间保留现有 `/` 与 `/day-1` URL，避免一次性重写全部页面。
- 未经用户明确要求，不发布或部署。
- 具体酒店未确定前，相关时间不得标为已验证。

## 验收标准

- 新增攻略只需新增攻略目录、填写 Schema 配置并注册加载入口。
- 通用首页、地图、动画和手账组件不需要因攻略内容变化而修改。
- 至少两套攻略可以按需加载，且不会把未选攻略打入首屏关键路径。
- 至少两种每日手账模板能渲染同一抽象模型。
- CI 可以遍历注册表，完成配置校验、静态渲染和关键交互测试。
- 关西攻略迁移前后的日期、停靠顺序、住宿地和返回时间一致。
