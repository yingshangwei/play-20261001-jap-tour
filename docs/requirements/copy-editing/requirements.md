# 页面文案改为直接说明行程和取舍

- [仓库文档地图](../../../MAP.md)
- [需求文档索引](../index.md)

## 当前问题

页面事实很多，但部分标题和导语更像宣传口号，用户需要继续读正文才能知道具体结论。相似句式反复出现，也让整页显得像统一模板生成。

优先处理这些类型：

| 当前表达 | 问题 | 改写方向 |
| --- | --- | --- |
| “九日关西，沿山林与烟火前行” | 有气氛，没有说清路线 | 直接说明 9 天日期、城市顺序和住宿安排 |
| “箱子先到位，人再轻装出发” | 省略日期和动作对象 | 写明 10.03 先到京都酒店交箱，再去岚山 |
| “真实地图，一眼看清是否顺路” | “真实”“一眼看清”无法验收 | 说明地图能按日期筛选点位和局部路线 |
| “参考旧行程，但不被它绑住” | 拟人化，结论不明确 | 写明保留哪些顺路内容，删除哪些重复或折返 |
| “城阳秋花火，是这趟旅行的时间锚点” | 抽象词掩盖实际约束 | 写明 10.04 必须 16:00 到场、19:00 开始 |
| “让路线保持松弛的五件事” | “松弛”含义不具体 | 写成减少早起、折返和超量步行的 5 条规则 |
| Day 1“沿着心斋桥的屋顶慢慢走到霓虹和石板路” | 画面感强，但路线信息弱 | 保留少量气氛，先说落地、入住、晚餐和收工时间 |

## 改写要求

1. 页面第一屏先回答：什么时候去、去哪里、住哪里、哪些项目不能移动。
2. 标题直接写结论或动作，不用“呼吸、松弛、锚点、绑住”等抽象词代替信息。
3. 每段只完成一个任务；先写结论，再写时间、地点、原因和备选。
4. 明确区分事实、建议、估算和待确认内容，不能把推测写成已核结果。
5. 行程取舍要写成“保留什么、删除什么、为什么”，不写笼统的“高价值主线”。
6. 餐厅文案先写适合日期、预算、预约条件和风险，再写风格描述。
7. 交通文案保留运营方、线路、时间和安全边界，删除重复铺垫。
8. 减少连续使用“先……再……”“不是……而是……”“只……不……”等模板句式。
9. 保留必要的旅行感，但每个页面最多设置一处纯氛围文案，不能影响信息查找。
10. 不增加原文没有的数据、体验结论或因果关系。

## 修改范围

- 首页标题、导语、章节标题、路线说明、取舍说明、餐厅介绍和页脚。
- `TripMap` 的图例、提示、交通说明和未定酒店提示。
- `JourneyPlayer` 的操作说明、步骤文案和占位说明。
- Day 1 及后续每日手账的标题、导语、提示、推荐理由和应变说明。
- 页面 metadata、按钮和链接文字。

不修改地名、线路名、时间、价格、来源名称和 [旅行约束](../kansai-2026/constraints.md) 中的固定事实；发现事实缺口时标为待确认，不靠润色补齐。

## 执行顺序

1. 先给所有公开文案标记“保留、改写、需核实”。
2. 先改首页第一屏、日程标题和关键决策，再改说明性长段落。
3. 再改地图、动画和每日手账中的操作文案。
4. 最后统一日期、全半角标点、中英文空格和按钮动词。

## 验收标准

- 用户在首页 30 秒内能说出日期、城市顺序、住宿节奏和固定项目。
- 每个章节标题单独阅读时，能知道该章节给出的结论或动作。
- 抽查文案时，事实、建议、估算和待确认状态可区分。
- 删除口号后没有丢失固定锚点、交通边界、行李要求或风险提示。
- 桌面和移动端没有因文字变化出现截断、溢出或按钮换行问题。
